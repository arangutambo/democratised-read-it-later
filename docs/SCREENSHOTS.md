# Screenshots to take

Four images, all referenced by the README. Save each into `docs/images/` with
the filename in the table — the links already point there, so they appear the
moment you commit them.

**Vault:** `~/Documents/Demo Vault`. It already contains two demo documents:

- `Sources/_decks/Multiple Sequence Alignment (demo).pdf` — a two-column page,
  which is the right thing to photograph because it is the case selection used
  to get wrong.
- `Sources/_decks/Why Reading Tools Keep Failing (demo).html` — an article with
  a remote image, so the blocked-image placeholder is visible.

**Window:** around 1440×900. Wide enough for the reader and the note side by
side, small enough that text stays legible when GitHub scales it down on a
phone.

## Before you shoot

- **Default Obsidian theme.** A reviewer sees the default; a screenshot in your
  own theme makes the plugin look like it ships that styling.
- **Nothing personal on screen.** Use the demo vault — that is what it is for.
  Check the file explorer and any open tab, not just the pane you meant to
  capture.
- **PNG, cropped to the Obsidian window**, not the whole desktop.
- **Real prose in the note.** The hero shot is an argument that you write in
  these notes; a note containing "asdf" argues the opposite.
